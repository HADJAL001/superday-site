# Координация — superday-site (лендинг SUPER DAY)

> Документ для синхронизации между Клодами-агентами проекта «Оптимизатор дня» /
> SUPER DAY. Прежде чем править этот репозиторий — прочитай раздел «Границы».

## Границы ответственности

- **Этот репозиторий (`HADJAL001/superday-site`, домен `superday.fun`)** —
  публичный маркетинговый лендинг. Зона Клода №3 (mobile / landing).
- Это **не** приложение и **не** бэкенд. Здесь нет auth, billing, API-логики.
  Всё, что касается ядра (ai-core), голоса (voice-core), инфраструктуры
  (auth/billing/infra) — в отдельных репозиториях и НЕ дублируется тут.
- Хостинг: **GitHub Pages** (файл `CNAME` = `superday.fun`). `netlify.toml`
  лежит как запасной конфиг, но живой деплой — Pages. Значит **Netlify Forms
  здесь не работают** — для сбора почт нужен внешний эндпоинт.

## Активация (шаги для основателя / ответственного Клода)

### 1. Сбор почт (Formspree — бесплатно, без бэкенда)
1. Зайти на https://formspree.io → создать форму (email = ящик, куда падают
   заявки, напр. `hello@superday.fun`).
2. Скопировать endpoint вида `https://formspree.io/f/xxxxxxx`.
3. В `index.html` найти `const WAITLIST_ENDPOINT = ""` и вставить туда URL.
4. Запушить. Всё — почты копятся в дашборде Formspree + приходят на ящик.
> Альтернативы без смены кода-контракта: любой сервис, принимающий
> `POST` с полем `email` и отвечающий `2xx` (Getform, Basin, свой Supabase
> Edge Function). При желании перейти на Supabase — согласовать с Клодом №4
> (инфра), т.к. это уже общий бэкенд.

### 2. Аналитика (GoatCounter — бесплатно, приватно, без cookies)
1. Зарегистрировать код на https://www.goatcounter.com (напр. `superday`).
2. В `index.html` раскомментировать блок `ACTIVATE-ANALYTICS` и подставить код.
> Аналог: Cloudflare Web Analytics или Plausible — тот же принцип, один тег.

## Правила для всех Клодов, кто трогает этот репозиторий

- Никаких фейковых отзывов, рейтингов, счётчиков подписчиков — только правда.
- Не коммитить секреты. Formspree/аналитика используют **публичные** id — это ок.
- Домен `superday.fun` уже привязан; HTTPS выпущен. Не отвязывать.
- Правки — аддитивные; палитра премиум-графит + приглушённое золото (см. `:root`).
- После правок: node-проверки (баланс CSS `{}`, `new Function` для JS,
  `JSON.parse` ld+json), затем `git push origin main`, проверить live.

## Харденинг безопасности и доступности (2026-07-25, Клод №3)

- **CSP + заголовки безопасности** через `<meta http-equiv>` (единственный путь
  на GitHub Pages) в `index.html` и `app.html`. Ключевое:
  `upgrade-insecure-requests`, `object-src 'none'`, `base-uri 'self'`.
  `script-src`/`connect-src` намеренно допускают `https:` — **чтобы будущая
  активация Formspree/аналитики (раздел «Активация») не сломалась**. Инлайн-стили
  и скрипты требуют `'unsafe-inline'`. Проверено headless Chrome: **0 CSP-нарушений**.
  ⚠️ При активации внешнего сервиса ничего в CSP менять не нужно (https уже разрешён);
  если захочется ужесточить до конкретных доменов — правь `connect-src`/`script-src`.
- **`referrer=strict-origin-when-cross-origin`** и **`color-scheme:dark`** (нативные
  контролы и скроллбар в тёмной гамме) в обоих файлах.
- **`prefers-reduced-motion`** теперь уважается и в `app.html` (был только в
  `index.html`) — универсальный сброс анимаций/переходов для вестибулярной
  чувствительности.
- `sw.js` поднят до `superday-v6`. При правках `app.html`/`index.html` —
  снова поднимать `CACHE`.
- **PWA-иконки исправлены** (`superday-v7`): manifest раньше объявлял только
  `1024×1024 purpose:any` — браузер слабо предлагал установку, Android-маска
  срезала логотип. Добавлены `assets/icon-192.png`, `icon-512.png` (any),

## Волна 8 — календарное измерение: регулярные дела + любая дата (2026-07-26, Клод №3)

Правки только в `app.html`, аддитивно. `sw.js` → `superday-v19`. **SCHEMA → 5**
(+`repeat`, +`doneOn`).

- **Проблема.** После волны 7 приложение знало ровно два дня: «сегодня» и «завтра».
  Регулярных дел не существовало — зарядку, планёрку, таблетки человек вбивал заново
  каждое утро (обходной путь — ручные «шаблоны дня», которые надо не забыть загрузить).
  Получалось наоборот тому, ради чего продукт сделан: **самое повторяемое дело требовало
  самого большого ручного труда.** Перенос тоже упирался в «завтра», хотя поле `defer`
  технически хранит любую дату.
- **Поле `repeat`** (`{days:[0..6]}` | `null`, 0=Вс). Регулярное дело **не порождает
  копии** — оно живёт одним объектом, а в «не свои» дни недели просто не считается
  сегодняшним: тот же механизм, что у переноса. Копии-инстансы плодили бы объекты и
  ломали статистику.
- **Единая точка правды — `isToday()` = `!isDeferred() && !isOffDay()`.** Одна правка, и
  повтор автоматически учли `planOrder`, счётчики квадрантов, сводка и бюджет дня,
  «Начни с этого» и тик напоминаний — без новых веток фильтрации. Тик напоминаний
  переведён с `isDeferred` на `isToday` (иначе регулярное дело звонило бы в чужой день).
- **Поле `doneOn`** — день отметки «выполнено». `resetRepeats()` на старте и в
  `checkNewDay()` снимает галочку у регулярного дела, если она стоит с прошлого дня.
  Отметка выполнения свелась к общему `markDone()` (было три места, где `done=true`
  ставился вручную: чекбокс, карточка «Начни с этого», «Готово» таймера фокуса).
- **`purgeDone()` — защита от потери правила.** «Убрать выполненные» и кнопка переноса
  дня раньше делали `filter(t => !t.done)` и **стёрли бы регулярное дело**. Теперь
  регулярное остаётся и сбрасывается в невыполненное; в `clearAll` `confirm` честно
  пишет, сколько правил повтора будет удалено.
- **Повтор прямо из речи и текста.** `parseRepeatPhrase()` понимает «каждый день»,
  «ежедневно», «по будням», «по выходным», «каждый вторник». Порядок разбора в
  `addTask` и в голосовом модуле: **повтор → длительность → время** (сначала снимаем
  «каждый день», иначе «день» мешает разбору времени). Список оборотов нарочно узкий,
  ложные отсечены тестами: «купить хлеб на день рождения», «отчёт за понедельник»,
  «планы на выходные», «совещание на целый день» → повтора нет.
- **Бейдж `.trep`** у дела: `＋повтор` / `🔁 каждый день` / `🔁 пн ср пт`. Клик —
  `editTaskRepeat` (prompt по образцу `editTaskTime`/`editTaskDur`, пусто = снять повтор).
  Дело в чужой день недели получает класс `.offday` (приглушено, как перенесённое) и
  не попадает в маршрут, бюджет, фокус и напоминания.
- **Перенос на любую дату.** `parseDay()` понимает «завтра», «послезавтра»,
  «понедельник» (ближайшее будущее), «через 3 дня», «28.07» (прошлое → следующий год),
  ISO; только будущее и не дальше года. `fmtDefer()` рисует подпись «→ завтра» /
  «→ пн 28» / «→ 15 авг». **Быстрый путь не изменился:** клик по `→ завтра` = завтра;
  диалог выбора дня открывается кликом по уже перенесённому делу. `setDefer` принимает
  дату (старый булев вызов поддержан).
- **Сохранность данных.** Всё живёт в `localStorage`, а браузер вправе его вычистить
  (Safari/iOS — после ~7 дней без визитов). `askPersistentStorage()` запрашивает
  `navigator.storage.persist()` — но только когда данных уже ≥3 дел, чтобы Firefox не
  показывал системный запрос случайному посетителю. Если постоянство не выдано, панель
  копий честно пишет: «Браузер может очистить данные при долгом простое».
- **Данные не теряются:** миграция v5 добавляет `repeat`/`doneOn` без потерь; экспорт
  `version:SCHEMA`, импорт и шаблоны дня переносят `repeat`; все точки создания дела
  пишут `repeat:null, doneOn:null`.
- Проверено: CSS `{}` 291/291, `new Function` по JS — OK (99 КБ); юнит-тесты логики,
  вытащенной **из живого файла** в Node — **78/78** (парсеры повтора и дат, форматтеры,
  матрица `isToday` × повтор × перенос, `resetRepeats`, `purgeDone`, `planOrder`,
  ложные срабатывания); интеграция в headless Chrome с реальным DOM — **28/28**
  (добавление фразой, исключение из счётчиков/маршрута/фокуса, «Убрать выполненные»
  не убивает регулярное, перенос на завтра → на дату → возврат, правка повтора
  диалогом, `doneOn`, шаблон дня); миграция **v4 → v5 без потерь — 14/14**;

## Следующее по ценности (кандидаты на волну 9+)

Ранжировано по «ценность на единицу кода», всё — чистый клиент, без бэкенда:

1. **Экспорт дня в `.ics` (с `VALARM`).** Самое честное ограничение продукта —
   «напоминания работают, пока открыта вкладка». Фоновый push требует бэкенда
   (`needs_backend`, Клод №4), **но системный календарь уже установлен на каждом
   устройстве**. Выгрузка дня в `.ics` с будильниками даёт настоящие фоновые
   напоминания без единого запроса к серверу. Максимальная ценность на единицу кода.
2. **Встроенные самотесты `app.html?selftest=1`.** Сейчас юнит-тесты вытаскиваются из
   живого файла в Node вручную при каждой волне. Тот же набор, запускаемый в живом
   браузере на живом коде, превращает разовую проверку в маховик качества.
3. **Утренний и вечерний ритуалы (по 2 минуты).** «Итог дня» есть, но входа и выхода
   из дня нет. Это замыкает петлю тревоги и превращает продукт в привычку.
4. **Контексты жизни** (работа / дом / здоровье) + баланс недели — отвечает «на что
   уходит жизнь», а не только «что успел».
5. **Клавиатура, одна рука, полный a11y-проход** — условие «стандартного» приложения.
6. **i18n (RU/EN).** Продукт русскоязычный на всех уровнях, включая парсеры. Парсеры
   уже изолированы в чистые функции — значит делается словарями, а не переписыванием.

Вне этого репозитория (`needs_backend`, зона Клода №4): аккаунты, синхронизация,
фоновый push, командный режим, AI-дебаты.
